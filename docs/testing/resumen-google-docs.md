## Punto 3: Backend, Swagger, endpoints y pruebas unitarias

En esta fase del proyecto se analizó, estructuró y documentó exhaustivamente el módulo backend del sistema (`backend-springboot`), el cual está implementado bajo una arquitectura limpia y modular utilizando **Java 21**, **Spring Boot 3.5.3**, persistencia relacional con **PostgreSQL/H2** (Spring Data JPA / Hibernate), control de versiones del esquema de base de datos con **Flyway** y mapeo eficiente de datos entre entidades y DTOs mediante **MapStruct** y **Lombok**.

La interfaz y los contratos de comunicación de la API REST fueron verificados y documentados en su totalidad siguiendo el estándar **OpenAPI 3.0** a través de la librería `springdoc-openapi`. Se validó la correcta disponibilidad de la interfaz gráfica interactiva **Swagger UI** en la ruta local `http://localhost:8080/swagger-ui/index.html` (y la especificación JSON en `/v3/api-docs`), permitiendo la exploración e interacción directa con todos los endpoints expuestos para la gestión integral de **Proyectos** (`/projects`) y **Tareas** (`/tasks`), comprobando los métodos HTTP, parámetros esperados y códigos de respuesta.

Asimismo, se auditó y validó la suite de calidad del software mediante pruebas automatizadas (unitarias y de integración) construidas sobre **JUnit 5**, **Mockito** y **MockMvc**. A través del comando Maven `mvn test` (y `.\mvnw.cmd test` en Windows), se confirmó la ejecución satisfactoria de las **42 pruebas automatizadas** del proyecto sin fallos ni errores, verificando las capas de dominio, repositorios, lógica de negocio en servicios y controladores REST, junto con la medición automática de cobertura mediante el plugin **JaCoCo**. Adicionalmente, se constató la compilación y validación integral del sistema con el comando `mvn clean install` (`.\mvnw.cmd clean install`).

Toda la documentación técnica desarrollada para el repositorio —incluyendo la arquitectura general del backend, la lista detallada de endpoints, los comandos de ejecución paso a paso y la sección de evidencias con referencias a las capturas de pantalla de la terminal (`mvn-test.png` y `mvn-clean-install.png`) y de la interfaz web (`swagger-ui.png`)— ha quedado organizada de manera clara y académica dentro del directorio `docs/testing/` y su subcarpeta `evidencias/`.
